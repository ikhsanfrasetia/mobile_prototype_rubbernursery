## 1. Executive Summary

Phase 9C successfully integrates the Master Data Cost Field Nursery Allocation (**CFNA**) established in Phase 9B into the Nursery Maintenance Module ([js/modules/maintenance/nursery-activity.js](file:///d:/PROJECT%20SOCFINDO/DATA%20SOCFIN/Project%20SIGMA/sigma-nursery/js/modules/maintenance/nursery-activity.js)). 

Key outcomes:
- **Context-Aware CFNA Dropdown**: When selecting an activity, only CFNA codes with `CONFIRMED` status are selectable.
- **Master Data as Single Source of Truth**: All allocation codes and canonical names are resolved directly from [js/data/cfna-master.js](file:///d:/PROJECT%20SOCFINDO/DATA%20SOCFIN/Project%20SIGMA/sigma-nursery/js/data/cfna-master.js).
- **Actor Identity & Audit Traceability**: Transactions created are automatically enriched with immutable actor snapshots via Phase 8B (`applyTransactionActor`).
- **100% Backward Compatibility**: Historical maintenance records without CFNA render gracefully with `"Tidak ada alokasi CFNA"` without mutation or data corruption.
- **Protected Core Preserved**: Zero changes to permissions, router, role profiles, user contexts, or session engines.

## 2. Maintenance Source Audit & Existing Transaction Structure

### Previous State:
Prior to Phase 9C, `nursery-activity.js` saved records into `storage.get('nursery_activity_records', [])` with basic activity, block, program, and worker items, without CFNA allocation codes and without centralized actor identity snapshotting.

### Integrated State:
Each new record created via `renderNurseryActivityForm` now captures:
- `allocationCode`: Canonical CFNA code (e.g., `'964009'`) or `null` if unmapped.
- `allocationName`: Canonical CFNA name (e.g., `'Penyiraman (Manual)'`) or `null` if unmapped.
- Full Phase 8B Actor Snapshot (`createdByUserId`, `createdByLoginCode`, `createdByName`, `createdByRole`, `createdByPosition`, `createdByEstateId`, `createdByDivisionId`, `createdByScopeType`, `auditTrail`).

## 4. Validation Rules Implemented

1. **Master Existence**: `allocationCode` must exist in `CFNA_MASTER`.
2. **Status Active**: `allocationCode` must have `status === 'ACTIVE'`.
3. **Confirmed Activity Mapping**: `allocationCode` must be confirmed for the selected activity.
4. **Canonical Name Guarantee**: `allocationName` is derived directly from `getCfnaByCode(code).name`, rejecting client-side spoofing.
5. **Graceful Fallback**: Unmapped activities store `null` for allocation fields without failing validation.

---

## 5. Actor Identity & Scope Preservation

- **Actor Snapshot**: Generated by `applyTransactionActor(record, 'CREATE')`.
- **Mantri Scope**: `MANTRI_TANAMAN` scope remains strictly `DIVISION`.
- **Estate & Same-Role Isolation**:
  - Wagiman (`TBS-MNT-001`, Tanah Besih) creates transactions with `estateId: 'EST-TBS'`, `divisionId: 'DIV-001'`.
  - Supriono (`APM-MNT-002`, Aek Pamingke) creates transactions with `estateId: 'EST-APM'`, `divisionId: 'DIV-APM-01'`.
  - Transactions between same-role users in different estates remain strictly partitioned.

---

## 6. Backward Compatibility with Historical Transactions

- **Historical Records**: Legacy maintenance records lacking CFNA fields render seamlessly in the UI accordion as `"Tidak ada alokasi CFNA"`.
- **No Mutations**: Zero automatic backfilling or migrations are performed on historical records.
- **No Crash**: `resolveTransactionActor(rec)` safely handles legacy transactions with `isLegacy: true`.
